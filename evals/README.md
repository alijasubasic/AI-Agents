# evals

Scored test cases for every agent, including the cases they fail.

```bash
make eval                      # the LOGIC layer: free, deterministic, runs in CI
python -m evals --layer judgement   # needs a live ANTHROPIC_API_KEY
```

---

## Two layers, deliberately kept apart

Every agent README in this repository says the same thing: the scripted mocks
prove the plumbing, not the prompt. This package is where that gap gets
**measured** instead of merely admitted.

| Layer | What it scores | Cost | Runs in CI |
|---|---|---|---|
| `LOGIC` | Deterministic code — policies, engines, verification | free | ✅ every commit |
| `JUDGEMENT` | The model's judgement, against the real API | tokens | ❌ opt-in |

Mixing them produces a single number that looks like quality and measures
neither: a suite that is 90% deterministic assertions and 10% model behaviour
reports "90%" no matter how badly the prompts perform. So every case declares
which layer it belongs to, and the runner never mixes them.

The LOGIC layer is the one that matters day to day. It is exact, it is free,
and it is what the improvement agent's verifier gate compares before and after
a patch.

## Known gaps are cases, not omissions

A case marked `KNOWN_GAP` documents a real limitation. It is kept, it fails,
and it fails *visibly* in the runner's output. Deleting it would make the score
look better and the agent no safer.

```
[gap ] intake-injection-detection-is-english-only
[gap ] triage-body-scan-misses-paraphrase
[gap ] research-misreading-a-real-quote-passes
[gap ] supervisor-cannot-release-a-false-escalation
```

Gaps are excluded from the headline score on purpose. Letting them drag the
number down creates pressure to delete them, which is exactly backwards —
their whole value is that they are written down.

The gaps worth reading first:

- **Both regex safety nets are English-only.** `triage-body-scan-is-english-only`
  and `intake-injection-detection-is-english-only`. This business takes German
  mail and German calls, so for most of the real inbox the safety net does not
  exist. That is the largest honest hole in the system.
- **Verification checks existence, not entailment.**
  `research-misreading-a-real-quote-passes`: a correct quote supporting a wrong
  conclusion scores `VERIFIED`. The sentence is checked; the inference from
  sentence to value is not.
- **Monotonic supervision cannot undo a mistake.**
  `supervisor-cannot-release-a-false-escalation` is the deliberate cost of
  [ADR 0005](../docs/adr/0005-monotonic-supervision.md), stated as a scored case
  so it stays visible rather than living only in prose.

## A gap that starts passing is news

`CaseResult.as_expected` compares the outcome to what the case *said* would
happen. A `KNOWN_GAP` that fails is behaving as documented. A `KNOWN_GAP` that
**passes** means somebody fixed it and forgot to update the case — so the
runner reports it as a surprise and exits non-zero.

That mechanism has already earned its place. The first run of this suite
flagged `booking-half-hour-offset-zones` as unexpectedly passing, which
surfaced an overstated claim in `scheduling.py`: half-hour-offset zones like
Asia/Kolkata are **fine** with a 15- or 30-minute grid, and only `:45` offsets
(Asia/Kathmandu) land on odd local minutes. The docstring, the agent README and
the case were all wrong in the same way, and the eval caught it.

## Writing a case

Metadata sits next to the assertion, which is the difference between a case
list that stays accurate and one that rots:

```python
@case(
    id="triage-body-scan-catches-refund",
    agent="email-triage",
    layer=Layer.LOGIC,
    description="A benign-looking invoice query is held because the body says 'refund'.",
)
def _() -> Score:
    result, sent, _ = _triage("msg-003")
    return combine(
        is_true(result.classification.confidence >= 0.75, label="model was confident"),
        is_true(result.requires_human, label="escalated anyway"),
        is_false(sent, label="not sent"),
    )
```

Scores are floats in `[0, 1]`, not booleans. An extraction that gets four of
five fields right is not the same as one that gets none, and a suite that
cannot tell them apart cannot show an improvement.

A case that raises is scored zero and reported. A suite that halts on the first
broken case tells you about one problem; one that finishes tells you about all
of them.

## Limitations

- **The JUDGEMENT layer has no cases yet.** The harness supports it and the
  runner accepts `--layer judgement`, but nobody has written the cases that
  would score prompt quality against the live API. That is the honest state:
  the scaffolding exists, the measurement does not.
- **Scoring never uses a model.** Model-graded scoring is a legitimate
  technique and a bad fit here — it would make the eval numbers themselves
  sampled, which is the exact property the LOGIC layer exists to avoid. It
  would be the right choice for the JUDGEMENT layer.
- **Agents are weighted equally, cases are not weighted at all.** An agent with
  forty cases must not drown out one with ten, so the report averages per
  agent. Within an agent, a trivial case counts as much as a critical one.
- **The suite scores behaviour, not coverage.** Nothing here notices a code
  path that no case touches. `pytest --cov` answers that question and is a
  separate tool for a separate purpose.
- **Known gaps are self-reported.** They document the limitations somebody
  thought of. The ones nobody thought of are, by construction, absent.
